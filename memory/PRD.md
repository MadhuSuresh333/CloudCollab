# CloudCollab - Product Requirements Document

## Original Problem Statement
Analyze this existing CloudCollab project. It was partially generated by Google Antigravity and already contains a backend and frontend scaffold. First determine what has already been implemented, then continue implementing the remaining features. Preserve existing code and only modify files when necessary.

## Overview
CloudCollab is a modern collaborative workspace platform that combines team management, document collaboration, file sharing, and project/task management into one unified experience.

## Architecture
- **Backend**: FastAPI + MongoDB (Motor async driver) + JWT authentication + Bcrypt password hashing
- **Frontend**: React 19 + React Router + shadcn/ui + Tailwind CSS + Axios
- **File Storage**: Local filesystem at `/app/backend/uploads`

## Core User Personas
1. **Team Lead/Owner**: Creates workspaces, invites members, manages projects
2. **Team Member**: Collaborates on documents, uploads files, works on tasks
3. **Administrator**: Manages members, has elevated permissions within a workspace

## Core Features

### 1. Authentication & User Management
- Email/password registration with JWT tokens
- Login/logout functionality
- Protected routes with automatic redirect
- User profile management

### 2. Workspace Management
- Create/edit/delete workspaces
- Invite members by email
- Role-based access (owner, admin, member)
- View all workspaces user is a member of

### 3. Document Collaboration
- Create documents within workspaces
- Edit document title and content
- Delete documents (creator or admin/owner)

### 4. File Management
- Upload files to workspace
- List files with size and upload metadata
- Delete files (uploader or admin/owner)

### 5. Project & Task Management
- Create projects within workspaces
- Kanban board with To Do, In Progress, Done columns
- Create tasks with title, description, status, priority, assignee
- Status changes via dropdown
- Priority levels (low, medium, high) with color badges

### Real-time Collaboration (NEW - Jan 2026)
- WebSocket endpoint: `/api/ws/documents/{document_id}?token=<jwt>`
- Message types: `active_users`, `content_change`, `title_change`, `cursor`, `ping`
- Presence indicators (colored avatar chips) in DocumentEditor
- Live/Offline connection status
- Changes auto-persist to MongoDB via fire-and-forget debounced writes
- Server does not echo sender's own messages (loop-free)

### File Validation (NEW - Jan 2026)
- Configurable size limit via `MAX_FILE_SIZE_MB` env var (default: 10MB)
- Whitelist of allowed extensions (images, docs, spreadsheets, presentations, archives, code, small audio/video)
- Public `/api/config` endpoint exposes limits to frontend
- Client-side validation prevents unnecessary requests
- Server-side validation returns 413 (too large) / 400 (bad type) with clear error messages

## Technical Notes

### Security Considerations
- JWT_SECRET_KEY should be changed for production
- CORS_ORIGINS should be restricted (currently '*')
- File uploads have no size/type validation - add for production
- Passwords hashed with bcrypt

### Known Limitations
- Documents use plain textarea (no rich text editor)
- No real-time collaboration
- File storage is local (should use S3 for production)
- Invitees must already exist as users (no email invitations)
